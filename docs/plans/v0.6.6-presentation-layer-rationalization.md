## Audit discoveries accepted into the v0.6.6 design

### Idle-history amplification

**Status: root cause proven; canonical v1 repair design approved and scheduled
as implementation Tasks 10–13.**

The production-like `nim-proxy_history` volume was inspected read-only on
2026-07-29. At the measurement boundary, `history.jsonl` was 235,920,090 bytes
across 7,680 records, spanning 2026-07-03 through 2026-07-29. Of 7,238
non-empty metric snapshots, 7,099 were semantically identical to the preceding
snapshot after normalizing Prometheus line order. Those repeats were 98.08% of
the comparable snapshots and occupied 230,517,600 bytes.

The cause is the unconditional five-minute append of the complete cumulative
Prometheus registry. Raw exposition order changes even when metric values do
not, so raw-string comparison is not a valid unchanged test. The traffic
created the metric series; idle sampling then rewrote them for weeks.

Required outcome:

- Preserve the five-minute time anchors, boot/reset boundaries,
  contemporaneous capacity, exact range totals, and days-based retention.
- Stop persisting a full exposition payload when its bounded metric state is
  semantically unchanged.
- Replace the experimental history rows with one unambiguously discriminated
  canonical format called `nimproxy-history/v1` at `history-v1.jsonl`.
  Experimental `history.jsonl` remains untouched and unread, and dashboard
  history resets; no compatibility reader, rotation, or migration is carried.
- Prove the repair first against a committed, sanitized reproduction derived
  from the observed corpus. The proof must fail on the current unconditional
  full-snapshot behavior and must compare rollup output before and after the
  storage optimization.

The first deliverable remains the committed regression check; the selected
implementation is the canonical codec, fail-closed store, explicit recovery
completeness, and atomic retention sequence in Tasks 10–13.

### NIM response-shape validation

**Status: normalized evidence audited; bounded capture, sanitization, and
observation work approved as implementation Tasks 14–16.**

`history.jsonl` contains Prometheus snapshots, not request or response bodies.
Rambler's tournament artifacts retain normalized completion content, reasoning,
finish reason, usage, and response model/id, but not the complete upstream HTTP
response envelope.

The bounded tournament sample contained 18 normalized completions across six
models: 14 ended with `stop`, four with `length`, and all supplied internally
consistent prompt/completion/total token counts. Eleven retained reasoning
content, but none supplied
`usage.completion_tokens_details.reasoning_tokens`. The current proxy only
records reasoning-token metrics from that optional usage field, so real
reasoning output can coexist with a zero reasoning-token series. Seven samples
included `prompt_tokens_details`; two reported cached tokens.

Required outcome:

- Inventory every request- and response-shape assumption in `src/proxy.rs`
  against sanitized real evidence, including buffered and streamed responses.
- Distinguish unavailable metrics from measured zero; never infer a numeric
  value the upstream did not provide.
- Add committed response fixtures and parser tests before changing collection
  behavior. Normalized Rambler artifacts can validate usage variability, but
  raw-envelope and SSE fixture gaps require controlled evidence capture.
- Keep upstream responses transparent; preserve only the documented
  `stream_options.include_usage` request injection/fallback and
  `strict_passthrough` exception. Prompts, response content, model ids, client
  names, and other machine data are not localized.
- Document the observed NIM contract and remaining uncertainty in `knowledge/`
  as part of the same work item.
